# Server Actions (`actions`)

## Overview
Next.js Server Actions (`'use server'`) implementing core backend mutations and queries for authentication delegation (`auth.ts`), recruiter job-post ingestion and CRUD via Mastra agent (`job-post.ts`), recruiter challenge generation, dashboard aggregation, and closing via Mastra tool and GitHub repository provisioning (`challenge.ts`), idempotent candidate challenge forking with atomic per-challenge sequence numbering (`fork-challenge.ts`), candidate challenge submission and repo archiving (`submit-challenge.ts`), and Mastra workflow submission scoring (`scoring.ts`).

## Interface
- `signUpAction(formData: FormData): Promise<{ success: false; error: string | undefined } | Awaited<ReturnType<typeof authController.signUp>>>` — Delegates user signup with request headers to `authController.signUp` `[auth.ts:signUpAction]`
- `signInAction(formData: FormData): Promise<Awaited<ReturnType<typeof authController.signIn>> | { success: false; error: string }>` — Delegates user sign-in with request headers to `authController.signIn` `[auth.ts:signInAction]`
- `signOutAction(): Promise<Awaited<ReturnType<typeof authController.signOut>> | { success: false; error: string }>` — Delegates sign-out with request headers to `authController.signOut` `[auth.ts:signOutAction]`
- `getCurrentUserAction(): Promise<Awaited<ReturnType<typeof authController.getCurrentUser>>>` — Returns current authenticated user via `authController.getCurrentUser` `[auth.ts:getCurrentUserAction]`
- `getSessionAction(): Promise<Awaited<ReturnType<typeof authController.getSession>>>` — Returns current session via `authController.getSession` `[auth.ts:getSessionAction]`
- `checkUserRoleAction(role: string): Promise<boolean>` — Stubbed role check that always returns `false` `[auth.ts:checkUserRoleAction]`
- `isAdminAction(): Promise<boolean>` — Stubbed admin check that always returns `false` `[auth.ts:isAdminAction]`
- `canAccessAdminAction(): Promise<boolean>` — Stubbed admin-panel access check that always returns `false` `[auth.ts:canAccessAdminAction]`
- `type CreateChallengePreview = { challengeId: string; title: string; seniority_level: string; techStack: string[]; status: string }` `[challenge.ts:CreateChallengePreview]`
- `createChallenge(jobPostId: string): Promise<CreateChallengePreview | { error: string }>` — Generates challenge content from a completed recruiter-owned job post, optionally provisions a GitHub template repo, and inserts a `challenge` row `[challenge.ts:createChallenge]`
- `type AllSubmissionRow = { id: string; challengeId: string; challengeTitle: string; sequenceNum: number; score: number | null; recommendation: string | null; status: string; submittedAt: Date | null }` `[challenge.ts:AllSubmissionRow]`
- `listAllSubmissions(): Promise<AllSubmissionRow[]>` — Lists all candidate submissions across the recruiter's challenges, ordered by score (nulls coalesced to `-1`) desc then `submittedAt` desc `[challenge.ts:listAllSubmissions]`
- `type RecruiterChallengeDashboardRow = { id: string; title: string; seniority_level: string; tech_stack: string; engineering_category: string; status: string; createdAt: Date | string | null }` `[challenge.ts:RecruiterChallengeDashboardRow]`
- `type ChallengeSubmissionStats = { n: number; topScore: number | null }` `[challenge.ts:ChallengeSubmissionStats]`
- `listRecruiterChallengesDashboard(): Promise<{ challenges: RecruiterChallengeDashboardRow[]; statsById: Record<string, ChallengeSubmissionStats> } | { error: string }>` — Lists recruiter-owned challenges alongside per-challenge submission counts and top scores `[challenge.ts:listRecruiterChallengesDashboard]`
- `closeChallenge(challengeId: string): Promise<{ ok: true } | { error: string }>` — Transitions a recruiter-owned challenge to `status = 'closed'` `[challenge.ts:closeChallenge]`
- `forkChallenge(challengeId: string): Promise<{ submissionId: string; forkName: string; cloneUrl: string } | { error: string }>` — Idempotently provisions a candidate-specific GitHub fork and `candidateSubmission` row with an atomically assigned `sequenceNum` `[fork-challenge.ts:forkChallenge]`
- `processJobPost(formData: FormData): Promise<{ success: true; data: { jobPostId: string; extractedData: JobPostData } } | { success: false; error: { code: string; message: string } }>` — Extracts text from an uploaded job post file, structures it via Mastra `jobPostProcessorAgent`, validates with `jobPostSchema`, and inserts a `jobPost` row `[job-post.ts:processJobPost]`
- `getJobPost(jobPostId: string): Promise<{ success: true; data: typeof jobPost.$inferSelect } | { success: false; error: { code: string; message: string } }>` — Fetches a single `jobPost` record by ID `[job-post.ts:getJobPost]`
- `listJobPosts(): Promise<{ success: true; data: Array<typeof jobPost.$inferSelect & { challengeGenerated: boolean; challengeId: string | null }> } | { success: false; error: { code: string; message: string } }>` — Lists the recruiter's job posts annotated with challenge generation status and latest `challengeId` `[job-post.ts:listJobPosts]`
- `deleteJobPost(jobPostId: string): Promise<{ success: true } | { success: false; error: { code: string; message: string } }>` — Deletes a recruiter-owned job post when no challenges reference it `[job-post.ts:deleteJobPost]`
- `triggerScoring(submissionId: string): Promise<{ ok: boolean } | { error: string }>` — Fetches the submitted fork's repo tree from GitHub, marks the submission `'scoring'`, and runs Mastra `scoreSubmissionWorkflow` `[scoring.ts:triggerScoring]`
- `submitChallenge(submissionId: string): Promise<{ ok: boolean } | { error: string }>` — Archives the candidate's GitHub fork, marks the submission `'submitted'` with `submittedAt`, and fires `triggerScoring` asynchronously `[submit-challenge.ts:submitChallenge]`

## Invariants
- All six modules declare the Next.js `'use server'` directive `[auth.ts:'use server']` `[challenge.ts:'use server']` `[fork-challenge.ts:'use server']` `[job-post.ts:'use server']` `[scoring.ts:'use server']` `[submit-challenge.ts:'use server']`
- `signUpAction`, `signInAction`, and `signOutAction` catch all thrown errors and return `{ success: false, error: (error as Error).message }`; `signUpAction` explicitly normalizes `!result.success` into `{ success: false, error: result.error }` `[auth.ts:signUpAction,signInAction,signOutAction]`
- `checkUserRoleAction`, `isAdminAction`, and `canAccessAdminAction` have their `authController` calls commented out and unconditionally return `false` `[auth.ts:checkUserRoleAction,isAdminAction,canAccessAdminAction]`
- `createChallenge`, `listAllSubmissions`, `listRecruiterChallengesDashboard`, and `closeChallenge` require an authenticated session (`authController.requireSession(await headers())`) and enforce `sessionUser.role === 'recruiter'` (returning `{ error: 'Unauthorized' }`, or `[]` in `listAllSubmissions`) `[challenge.ts:createChallenge,listAllSubmissions,listRecruiterChallengesDashboard,closeChallenge]`
- `createChallenge` requires the target `jobPost` to exist (`'Job post not found'`), match `post.recruiterId === recruiterId` (`'Unauthorized'`), and have `processingStatus === 'completed'` (`'Job post is not ready'`) `[challenge.ts:createChallenge]`
- `createChallenge` only calls GitHub repo provisioning when both `process.env.GITHUB_APP_ID` and `process.env.GITHUB_APP_PRIVATE_KEY` are set; if skipped or if creation throws, `githubRepoName` stays `null` and `challenge.status` is saved as `'draft'`, otherwise `'active'` `[challenge.ts:createChallenge]`
- `createChallenge` defaults `location_country = 'Remote'`, `location_city = ''`, `remote = true`, `equity = false`, `salary_range_min/max = 0`, `currency = 'USD'`, `requiredSkills = []`, JSON-stringifies `requiredSkills` into `tech_stack`, and casts `post.experienceLevel` to `'junior' | 'mid' | 'senior' | 'lead'` `[challenge.ts:createChallenge]`
- `closeChallenge` verifies challenge existence and `creatorId === sessionUser.id` (`'Challenge not found'`), scopes the `UPDATE` predicate to both `id` and `creatorId`, and sets `status = 'closed'` `[challenge.ts:closeChallenge]`
- `forkChallenge` enforces candidate role via `requireRole('candidate')` and requires `process.env.GITHUB_APP_ID`, `process.env.GITHUB_APP_PRIVATE_KEY`, and module-level `ORG = process.env.GITHUB_ORG_NAME` (`'GitHub integration not configured.'`) `[fork-challenge.ts:ORG,forkChallenge]`
- `forkChallenge` rejects missing challenges (`'Challenge not found.'`), `'draft'` challenges (`'This challenge is not available yet.'`), non-`'active'` challenges (`'This challenge is not available.'`), and challenges lacking `githubRepoName` (`'Challenge repository is not ready.'`) `[fork-challenge.ts:forkChallenge]`
- `forkChallenge` is idempotent per `(challengeId, candidateId)`: an existing `candidateSubmission` returns its `submissionId`, `githubForkName`, and `https://github.com/${ORG}/${existing.githubForkName}.git` without incrementing `sequenceNum` or re-forking `[fork-challenge.ts:forkChallenge]`
- `forkChallenge` assigns `sequenceNum` atomically inside a DB transaction on `challenge_counter` (throwing `'Failed to assign sequence number'` if null or `< 1`), builds `candidateAlias` as ``cand-${sequenceNum}``, and inserts `candidateSubmission` with initial `status = 'forked'` `[fork-challenge.ts:forkChallenge]`
- `processJobPost` requires session (`authController.requireSession`), enforces `formData.get('file')` presence (`'MISSING_FILE'`) and `sessionUser.role === 'recruiter'` (`'FORBIDDEN'`), derives `recruiterId` strictly from the session, propagates `FileValidationError` codes/messages, requires non-empty `result.toolResults` (`'EXTRACTION_FAILED'`), validates extracted output via Zod `jobPostSchema.safeParse` (`'EXTRACTION_FAILED'`), persists `processingStatus = 'completed'`, and masks unexpected errors as `'PROCESSING_FAILED'` `[job-post.ts:processJobPost]`
- Internal `extractJobPostFromToolResults` recursively scans wrapper keys `['result', 'output', 'object', 'data', 'payload']` and arrays for objects with non-empty string `title`/`company`/`description`, `type` in `['full-time', 'part-time', 'contract', 'internship']`, `experienceLevel` in `['junior', 'mid', 'senior', 'lead']`, and array `requiredSkills` `[job-post.ts:extractJobPostFromToolResults]`
- `getJobPost` performs no session, role, or ownership check; returns `'NOT_FOUND'` when missing and `'FETCH_FAILED'` on error `[job-post.ts:getJobPost]`
- `listJobPosts` enforces recruiter role (`'FORBIDDEN'`), scopes queries to `sessionUser.id`, and links each job post to its most recently created challenge `[job-post.ts:listJobPosts]`
- `deleteJobPost` enforces recruiter role (`'FORBIDDEN'`), verifies existence (`'NOT_FOUND'`) and ownership (`post.recruiterId === sessionUser.id`, else `'FORBIDDEN'`), and blocks deletion if any challenge references `jobPostId` (`'HAS_CHALLENGES'`) `[job-post.ts:deleteJobPost]`
- `triggerScoring` enforces authenticated `sessionUser.role === 'candidate'` (`'Unauthorized'`), verifies submission existence (`'Submission not found'`), ownership (`submission.candidateId === sessionUser.id`, else `'Unauthorized'`), `status === 'submitted'` (`'Submission is not ready for scoring'`), `GITHUB_APP_ID`/`GITHUB_APP_PRIVATE_KEY` (`'GitHub integration is not configured'`), and truthy `submission.githubForkName` (`'Missing fork for submission'`) `[scoring.ts:triggerScoring]`
- `triggerScoring` transitions `candidateSubmission.status` from `'submitted'` to `'scoring'` before running the workflow, and sets `status = 'failed'` if workflow creation or execution throws `[scoring.ts:triggerScoring]`
- `submitChallenge` enforces `requireRole('candidate')`, verifies submission existence (`'Submission not found'`), ownership (`submission.candidateId === sessionUser.id`, else `'Unauthorized'`), `status === 'forked'` (`'Already submitted'`), and `GITHUB_APP_ID`/`GITHUB_APP_PRIVATE_KEY` (`'GitHub integration not configured'`) `[submit-challenge.ts:submitChallenge]`
- `submitChallenge` transitions `candidateSubmission.status` from `'forked'` to `'submitted'` with `submittedAt: new Date()` only after archiving the GitHub fork, and triggers `triggerScoring` fire-and-forget without awaiting completion `[submit-challenge.ts:submitChallenge]`

## Side Effects
- Reads Next.js request headers via `headers()` and invokes `authController.signUp`, `signIn`, `signOut`, `getCurrentUser`, `getSession`, and `requireSession`, plus `requireRole('candidate')` `[auth.ts:signUpAction,signInAction,signOutAction,getCurrentUserAction,getSessionAction]` `[challenge.ts:createChallenge,listAllSubmissions,listRecruiterChallengesDashboard,closeChallenge]` `[fork-challenge.ts:forkChallenge]` `[job-post.ts:processJobPost,listJobPosts,deleteJobPost]` `[scoring.ts:triggerScoring]` `[submit-challenge.ts:submitChallenge]`
- Executes Mastra AI tools, agents, and workflows: `challengeGeneratorTool.execute!` `[challenge.ts:createChallenge]`, `mastra.getAgent('jobPostProcessorAgent').generate(...)` `[job-post.ts:processJobPost]`, and `mastra.getWorkflow('scoreSubmissionWorkflow').createRun()` / `run.start(...)` `[scoring.ts:triggerScoring]`
- Calls external GitHub API helpers via `@/lib/github`: `github.createChallengeRepo` `[challenge.ts:createChallenge]`, `github.forkChallengeRepo` `[fork-challenge.ts:forkChallenge]`, `github.getRepoTree` `[scoring.ts:triggerScoring]`, and `github.archiveFork` `[submit-challenge.ts:submitChallenge]`
- Performs Drizzle DB reads and mutations across `jobPost` (`SELECT`, `INSERT`, `DELETE`), `challenge` (`SELECT`, `INSERT`, `UPDATE`), `candidateSubmission` (`SELECT`, `INSERT`, `UPDATE`), and raw SQL transactions on `challenge_counter` (`INSERT OR IGNORE`, `UPDATE`, `SELECT`) `[challenge.ts:createChallenge,listAllSubmissions,listRecruiterChallengesDashboard,closeChallenge]` `[fork-challenge.ts:forkChallenge]` `[job-post.ts:processJobPost,getJobPost,listJobPosts,deleteJobPost]` `[scoring.ts:triggerScoring]` `[submit-challenge.ts:submitChallenge]`
- Parses uploaded job-post files via `getFileMetadata` and `extractTextFromFile` `[job-post.ts:processJobPost]`
- Triggers background asynchronous scoring via unawaited `triggerScoring(submissionId)` `[submit-challenge.ts:submitChallenge]`
- Emits operational/error logs via `logError` and `console.log`/`console.warn`/`console.error` `[challenge.ts:createChallenge,listRecruiterChallengesDashboard,closeChallenge]` `[fork-challenge.ts:forkChallenge]` `[job-post.ts:processJobPost,getJobPost,listJobPosts,deleteJobPost]` `[scoring.ts:triggerScoring]` `[submit-challenge.ts:submitChallenge]`
